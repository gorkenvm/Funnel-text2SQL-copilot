Where formatting is applied (one choke point per response path, no double-formatting)
-----------------------------------------------------------------------------------------
- src/agent/sqlfmt.py                 format_sql_for_display(sql) -> str
                                       lazy `import sqlparse`; returns input unchanged on
                                       None/non-string/empty input, missing dependency, or
                                       any exception from sqlparse.format(). Never raises.
- src/agent/agent.py  FunnelAgent._payload()      the single choke point for BOTH
                                       ask() and run_metric()'s success path (used by
                                       /api/ask and /api/dashboard's card assembly).
                      FunnelAgent.ask() refused/error early returns  formatted at each
                                       return site (still a single format call per path).
- src/agent/agentic.py AgenticFunnelAgent.run()    the "sql" trace event (formats
                                       arguments["sql"] for display only — the tool call
                                       itself still receives the LLM's original string)
                                       and the final "answer" event's `sql` field.
                      AgenticFunnelAgent._fallback_answer()  same "answer" event field,
                                       for the timeout/error/retry-exhausted paths.
- app/main.py                         unchanged: /api/ask copies agent.ask()'s already-
                                       formatted `sql` field verbatim (no second format
                                       call); /api/dashboard's card dicts never include a
                                       `sql` field at all, so there is nothing to format
                                       there.

The SQL that is actually validated/guardrailed/executed (agent.guardrails.validate_sql,
enforce_limit, driver.query, and every registry metric['sql'] used for execution) is
never touched by format_sql_for_display — only a separate display copy is formatted, at
the last moment before each response/event dict is built.
