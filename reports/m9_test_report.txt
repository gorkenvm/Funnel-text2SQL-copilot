4. ECharts theming (DESIGN.md §2)
-----------------------------------
Added a fixed 5-color categorical palette, assigned by first-seen entity
order (never by rank/value, never recycled per filter):
  CHART_PALETTE = ["#2F9E63","#3D72C0","#CE7A1A","#8B55C9","#C24E2A"]
Single-series charts (9 of the 12 registered metrics + funnel + pie + line)
use CHART_PALETTE[0] uniformly, matching "brand anchor, first series
always." The 3 metrics carrying a `series` field in metrics.yaml
(pairing_rate_by_platform_market -> platform, attribution_first_vs_last ->
attribution_model, completion_by_channel_device -> device_category) assign
PALETTE[i] per distinct series value in first-seen order and turn legend
on (text --ink-soft); every other chart has no legend (title names it).
Also added: axis/grid lines colored --border, axis labels --ink-muted,
bar borderRadius [4,4,0,0] (funnel's horizontal bars [0,4,4,0], rounded on
the data end), a 2px "gap" between adjacent bar/pie-slice fills via an
itemStyle borderColor=--surface/borderWidth=2 trick, tabular-nums kept on
all DOM-rendered numbers (stat tiles, latency/step-secs badges), and a
CHART_SEQUENTIAL_RAMP constant (#E7F0EA -> #9CCDB0 -> #468254 -> #154734)
defined but unused, reserved for a future heat/magnitude chart per §2.

6. Regression caught and fixed: mobile layout
------------------------------------------------
The new second footer line adds height to the footer on narrow viewports,
which — stacked with the pre-existing `.chat-panel{max-height:60vh}` mobile
rule — squeezed `.dash-panel` down to ~8px, pushing the dashboard toolbar
("Build top-12 KPI dashboard" button) underneath the footer and making it
unclickable (confirmed via a failed Playwright click before the fix, and
via bounding-box measurements). Fixed with two small, targeted rules in the
existing `@media (max-width:900px)` block: chat-panel cap lowered to 52vh,
and `.dash-panel{min-height:220px}` added so the toolbar always has room;
if total content still exceeds the viewport the page now scrolls as a
whole rather than clipping anything. Verified post-fix: button sits at
y=714-754px, footer starts at y=769px, no overlap; full mobile welcome and
mobile dashboard screenshots (f1/f2) confirm no visual regression.

9. DESIGN.md ambiguities resolved (and how)
-----------------------------------------------
  1. Brand <h1> font: §3's display-role list enumerates "welcome title,
     hero/stat numbers, card titles, section headers" — the page's own
     brand lockup ("Phonak Funnel Copilot — ...") isn't named. Kept it in
     Inter 700 rather than Fraunces, both because it's not on the list and
     because §0 already warns against anything that reads as a copied
     wordmark/logo treatment.
  2. No "--danger-soft" token exists in §1 for the error-message bubble
     background. Derived a light, bordered danger tint (#FBEAE7, paired
     with a 1px --danger border) rather than a flat fill, consistent with
     the "flat by default, hairline border" elevation rule in §4.
  3. hljs token roles beyond keyword/string/number/comment (built_in/type,
     operator/punctuation, variable/title/attr) aren't specified in §5.
     Kept them inside the same dark-surface green family (mid-green,
     grey-green, light neutral) rather than reintroducing the old teal, so
     the block still reads as one palette.
  4. Pie charts: §2 says "legend present for >=2 series, none for single
     series." A pie is always one echarts series regardless of slice
     count. Read literally: no legend on pie charts, relying on the
     existing per-slice on-chart name labels (which were already being
     rendered) to identify slices instead — this removed the old
     always-on bottom legend on the "pie" chart-type option (still
     available via each card's chart-type switcher).
  5. Segmented-control radius: §4 lists 4 explicit radius buckets (buttons/
     chips 8, inputs 10, cards/panels 16, pills 999) but doesn't name the
     tier/language toggle "capsule" container. Left it as a 999px pill
     container (as it already was) since it visually functions like the
     existing badge/citation-chip pills, not a standalone button.
  6. "2px gaps between adjacent fills... via barCategoryGap/borderWidth
     trick" — implemented as itemStyle.borderColor = --surface (white) +
     borderWidth: 2 on every bar/pie-slice fill, which reads as a gap
     against the card's white background while preserving the rounded-
     corner geometry; barGap/barCategoryGap's percentage-of-bar-width units
     don't give an exact pixel value, so the border trick was used as the
     spec names it.
  7. Table row hover "--accent-soft at 40%": implemented literally as
     rgba(231,240,234,.4) — a very subtle wash over white, consistent with
     the flat/hairline aesthetic the rest of §4/§5 calls for.

10. Deviations from the letter of DESIGN.md (documented, not silent)
------------------------------------------------------------------------
  - Chart axis/tooltip label text is drawn by ECharts on <canvas>, which
    does not support the CSS `font-variant-numeric: tabular-nums`
    property inside a canvas 2D font string in any browser. Tabular nums
    are applied everywhere they can actually take effect — stat tiles,
    latency badges, step-secs badges (all real DOM text) — but chart-axis
    numerals use the browser's default numeral rendering.
  - The `.woff` fallback files that ship alongside each fontsource woff2
    were intentionally not copied (task said "obtain ... woff2"; woff2 is
    universally supported by the target browsers/Playwright chromium), so
    there is no non-woff2 fallback format — only the system-stack font
    fallback described in §3 if the woff2 fails to load for some reason.
