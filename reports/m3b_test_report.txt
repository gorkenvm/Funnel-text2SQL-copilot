WHAT CAN ONLY BE VERIFIED ON THE USER'S OWN MACHINE
--------------------------------------------------------------------------------
This sandbox has no network access to Databricks or a browser to load the
vendored JS files against a real DOM outside jsdom, so the following are
NOT covered by the automated suite or by the manual checks above and need
the user's own verification (see docs/deploy_guide.md section 5 for the
exact steps):

1. Actually opening a Databricks Free Edition account, finding the SQL
   Warehouse "Server hostname" / "HTTP path", and generating a PAT.
2. Running `python scripts/load_to_databricks.py` against a REAL warehouse
   — the script's SQL generation and control flow are unit-tested, but the
   real PUT/staging-ingestion round trip, real Unity Catalog volume/schema
   creation, and real network-error surfaces (actual 403 text, actual DNS
   failure text, etc.) can only be observed live. The Turkish hint matcher
   was tested against representative error strings, not the exact strings
   Databricks' servers return.
3. Setting AGENT_DB=databricks in .env, restarting the app, and confirming
   GET /health returns {"driver": "databricks", ...} against the real
   warehouse (this sandbox only proves DatabricksDriver *would* call
   databricks.sql.connect(..., catalog=..., schema=...) correctly, via a
   fake module).
4. Visual/browser verification of the M3a UI polish in Part A: markdown
   rendering in a real browser (tables, bold, lists rendering visually
   correctly and matching the .md-table / .fallback-table look), the
   persistent <details class="trace-details"> collapsing/expanding
   correctly in the DOM after a live SSE answer, and the TR label
   "Ajan izini gör (N adım)" rendering correctly. This sandbox verified
   the JS logic (via jsdom + node --check) but not an actual rendered page.
5. Confirming a real LLM (OpenAI/Anthropic) actually follows the new
   system-prompt instruction to avoid markdown tables/headings in its
   final answer — the prompt text change itself is unit-tested
   (test_prompt_forbids_markdown_tables_and_headings), but model
   compliance can only be observed with a live API key, which this
   sandbox does not have.
